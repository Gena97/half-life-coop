# Автообновление Half-Life Co-op

Игрок открывает `hlcoop/start-hlcoop.cmd`: обновлятор проверяет последний стабильный GitHub Release, при наличии более новой версии скачивает готовый архив и запускает игру. Проверка также встроена в проектные скрипты через `scripts/launch.ps1`. Сама Half-Life и запуск приглашением Steam обновлятор не вызывают

## Настройки

В исходниках и готовом ZIP уже настроен репозиторий `Gena97/half-life-coop`. Параметры находятся в `game/hlcoop/update.json`, после установки — в `Half-Life/hlcoop/update.json`. Для своего репозитория замените поле `repository`. Оно сохраняется при следующих обновлениях

Если в старой ручной установке адрес остался пустым, укажите `Gena97/half-life-coop` один раз. Пустое поле отключает сетевую проверку

Git для работы обновлятора игроку не нужен. Токены доступа и вход в GitHub тоже не нужны; реализована загрузка из публичного репозитория

```json
{
  "schemaVersion": 1,
  "repository": "Gena97/half-life-coop",
  "enabled": true,
  "mode": "automatic",
  "assetPrefix": "hlcoop",
  "timeoutSeconds": 15
}
```

`enabled: false` отключает проверку. `mode: "notify"` сообщает о новой версии и запускает установленную. `mode: "automatic"` устанавливает обновление перед запуском

## Публикация через GitHub Actions

Workflow запускается при отправке тега вида `v0.4.7`. Номер должен совпадать с `version` в `game/hlcoop/liblist.gam`. Для следующей версии увеличьте номер, обновите описание изменений и сохраните изменения в Git

```powershell
git tag v0.4.7
git push origin v0.4.7
```

Команды отправляют тег в репозиторий, подключённый как `origin`

Workflow собирает Release Win32 на Windows, подставляет адрес собственного репозитория в пустую конфигурацию обновлений, создаёт архив и SHA256, загружает оба файла в черновик Release и публикует его после успешной загрузки. В настройках репозитория должны быть разрешены GitHub Actions и публикация релизов через `GITHUB_TOKEN`

Если тег уже опубликован, а запуск не появился, откройте **Actions → Release mod → Run workflow**. Выберите ветку `main`, в поле `release_tag` укажите существующий тег, например `v0.4.7`, и нажмите **Run workflow**. Ручной триггер должен быть сохранён в основной ветке репозитория

Ручной запуск берёт исходники именно из выбранного тега. Ветка `main` предоставляет сценарий запуска; номер в `liblist.gam` проверяется уже на исходниках тега. Удалять или переносить тег для повторной попытки не требуется

Изменение файлов в ветке без нового релиза не обновляет установленные копии. Для исправленной сборки выпускайте новый номер версии: одинаковую версию обновлятор повторно не устанавливает. Черновики, предварительные релизы и версии ниже установленной пропускаются

## Публикация вручную

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

Создайте GitHub Release с тегом `v0.4.7` и прикрепите:

- `artifacts/hlcoop-0.4.7-win32.zip`
- `artifacts/hlcoop-0.4.7-win32.zip.sha256`

Загружайте файлы в черновик, затем публикуйте релиз целиком. Используйте готовый пакет без `-IncludeSymbols`. Автоматический архив исходников GitHub `Source code (zip)` обновлятору не подходит

GitHub описывает формат релизов и вложений в [документации Releases API](https://docs.github.com/en/rest/releases/releases), порядок публикации — в [управлении релизами](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)

## Установка и сохранение данных

Проверяются SHA256 загруженного ZIP, внутренний манифест, размеры и хеши файлов, номер версии и допустимые пути. Существующие `*.cfg`, `settings.scr`, `CSBotConfig.vdf`, `update.json`, сохранения и журналы не заменяются. Файлы оригинальной Half-Life не входят в обновление

Играющие клиенты и серверы не завершаются. Если файлы заняты работающей игрой, установка откладывается до следующего запуска. Если GitHub недоступен или архив не прошёл проверку, остаётся установленная версия

Перед заменой файлов создаётся резервная копия. При ошибке установки выполняется откат. Если откат не завершён или предыдущая установка была прервана, запуск блокируется, чтобы не смешивать библиотеки разных версий; данные для восстановления находятся в `.hlcoop-update-transaction.json` установленного мода

Для проверки наличия релиза без установки и запуска игры:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\путь\Half-Life\hlcoop\update-hlcoop.ps1" -CheckOnly
```

В проектном `scripts/launch.ps1` параметр `-SkipUpdate` пропускает сетевую проверку. Он не разрешает запуск после незавершённой установки

## Ярлык на рабочем столе

В версии 0.4.7 первый запуск `start-hlcoop.cmd` создаёт ярлык **Half-Life Co-op** для текущего пользователя. Ярлык открывает тот же запускатель с проверкой обновлений. При автоматическом обновлении с 0.4.6 он появится при следующем открытии запускателя

Создать ярлык отдельно, без сетевой проверки и запуска игры:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\путь\Half-Life\hlcoop\update-hlcoop.ps1" -CreateShortcutOnly
```
