# Установка и обновление Half-Life Co-op

В версии 0.4.9 для установки и запуска мода достаточно одного `HLCoopLauncher.exe`. Положите его куда удобно, например на рабочий стол, и откройте

Нужны Windows и установленная оригинальная Half-Life из Steam. Half-Life: Source не подходит. Запускатель находит игру в библиотеках Steam, устанавливает встроенный пакет в `Half-Life/hlcoop` и запускает мод. Если найти игру не удалось, появится выбор папки с `hl.exe` и `valve`. Выбранная папка запоминается

Для следующих запусков открывайте этот же EXE, поэтому после установки его нужно оставить. Он обновляется на своём месте. Ярлыки не создаются, отдельная копия EXE в AppData не устанавливается. В `%LOCALAPPDATA%\HalfLifeCoop` хранятся выбранная папка игры и журналы

## Что происходит при следующих запусках

Запускатель проверяет последний стабильный GitHub Release. Если появился более новый EXE, он скачивается и проверяется по SHA256, формату Win32 PE и версии в ресурсах Windows. Отдельный служебный процесс ждёт закрытия текущего запускателя, ещё раз сверяет хеши, заменяет тот EXE, который вы открыли, и запускает новую версию. Если замена не удалась, восстанавливается прежняя копия; ошибка сохраняется в журнале внутри `%LOCALAPPDATA%\HalfLifeCoop`

Для загрузки и замены EXE рядом с ним временно создаётся скрытая папка `.hlcoop-update-GUID`. Она находится на том же диске, чтобы замена через `File.Replace` и откат работали без переноса между дисками. После успешного обновления папка удаляется

Затем проверяется установленный мод. Встроенный ZIP позволяет установить мод без скачивания пакета заново, а обновлятор мода получает более свежие версии из релизов. При недоступном GitHub используется доступная локальная версия. Во время работы игры файлы мода не заменяются

Обычный `hlcoop/start-hlcoop.cmd` тоже поддерживается: он проверяет и обновляет файлы мода. Проверка нового EXE выполняется при запуске `HLCoopLauncher.exe`. Сам запуск Half-Life и приглашение Steam проверку обновлений не вызывают

## Параметры EXE

Папку игры можно передать явно, например для второй установленной копии:

```powershell
.\HLCoopLauncher.exe --game-dir "F:\Games\Half-Life"
```

`--install-only` устанавливает или обновляет мод, затем завершает работу без запуска игры

`--skip-update` отключает сетевые проверки EXE и мода. Установка из встроенного пакета при этом работает. Для установки без сети и без запуска игры:

```powershell
.\HLCoopLauncher.exe --game-dir "F:\Games\Half-Life" --install-only --skip-update
```

## Настройки обновлятора мода

В исходниках и готовом пакете настроен публичный репозиторий `Gena97/half-life-coop`. Git и вход в GitHub игрокам не нужны

Параметры мода находятся в `Half-Life/hlcoop/update.json`:

```json
{
  "schemaVersion": 1,
  "repository": "Gena97/half-life-coop",
  "enabled": true,
  "mode": "automatic",
  "assetPrefix": "hlcoop",
  "timeoutSeconds": 15
}
```

`enabled: false` отключает проверку мода, `mode: "notify"` сообщает о новой версии без её установки, `mode: "automatic"` устанавливает обновление перед запуском. Пустой `repository` отключает сетевую проверку мода. Эти настройки не управляют обновлением самого EXE; для пропуска обеих проверок есть `--skip-update`

Для собственного репозитория измените адрес в исходном `game/hlcoop/update.json` перед сборкой. Он также встраивается в EXE. Уже существующий `update.json` у игрока сохраняется при обновлениях

## Сохранение данных

Установщик проверяет SHA256 ZIP, внутренний манифест, размеры и хеши файлов, номер версии и допустимые пути. Существующие `*.cfg`, `settings.scr`, `CSBotConfig.vdf`, `update.json`, сохранения и журналы не заменяются. Оригинальные файлы Half-Life не входят в пакет

Перед заменой файлов мода создаётся резервная копия. При ошибке выполняется откат. Если откат не завершён или предыдущая установка была прервана, запуск блокируется; путь к резервной копии записан в `hlcoop/.hlcoop-update-transaction.json`

Проверить наличие обновления мода без установки и запуска игры:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\путь\Half-Life\hlcoop\update-hlcoop.ps1" -CheckOnly
```

## Выпуск через GitHub Actions

Workflow запускается при отправке тега вида `v0.4.9`. Номер должен совпадать с `version` в `game/hlcoop/liblist.gam`. После сохранения изменений в Git:

```powershell
git push origin main
git tag v0.4.9
git push origin v0.4.9
```

Workflow собирает библиотеки мода, создаёт ZIP, затем собирает запускатель с этим ZIP внутри. В черновик Release загружаются четыре файла, после успешной загрузки релиз публикуется:

- `hlcoop-0.4.9-win32.zip`
- `hlcoop-0.4.9-win32.zip.sha256`
- `HLCoopLauncher.exe`
- `HLCoopLauncher.exe.sha256`

ZIP нужен для ручной установки и обновляторов прошлых версий. EXE публикуется отдельно и в ZIP мода не входит

Если тег уже отправлен, откройте **Actions → Release mod → Run workflow**, выберите `main` и укажите существующий тег в поле `release_tag`. Ручной запуск берёт исходники из выбранного тега. Удалять или переносить тег для повторной попытки не нужно

Изменение файлов в ветке без нового релиза не обновляет установленные копии. Для исправленной сборки выпускайте новый номер: одинаковая версия повторно не устанавливается. Черновики, предварительные релизы и версии ниже установленной пропускаются

## Сборка и публикация вручную

Нужны Visual Studio 2022 с инструментами C++ для x86/x64 и Windows SDK. Выполняйте команды по порядку: EXE должен встраивать уже готовый ZIP текущей версии

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\package.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-launcher.ps1
```

Готовые файлы находятся в `artifacts`. При необходимости передайте `build-launcher.ps1` параметры `-PackagePath` и `-OutputDirectory`

Создайте GitHub Release с тегом `v0.4.9`, загрузите четыре файла из списка выше в черновик, затем опубликуйте релиз целиком. Используйте пакет без `-IncludeSymbols`. Автоматический архив GitHub `Source code (zip)` для установки мода не подходит

## Что проверено

16 октября 2026 года на отдельную копию 0.4.5 добавлен обновлятор из релиза 0.4.6 и проверена загрузка настоящего GitHub Release 0.4.6. Архив скачан и установлен, настройки, сохранения и журналы сохранились без изменений. Проверка не меняла пользовательскую установку игры

Предыдущая сборка EXE 0.4.8 проверена с `--install-only --skip-update` на отдельной папке с пробелами и кириллицей в пути. Первая установка завершилась, все 24 файла совпали с манифестом. Игра не запускалась, файлы рабочей установки остались прежними

После этого запускатель изменён: теперь он работает из выбранного пользователем места и не создаёт ярлыки. Эта сборка ещё не запускалась. Версия 0.4.9 пока не опубликована

Самообновление EXE через настоящий GitHub Release пока не проверено от начала до конца: для этого нужен опубликованный релиз запускателя со следующим номером версии
